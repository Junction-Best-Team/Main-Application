# Recipe illustrations in chat

The assistant can call `generate_recipe_image` with a dish and a short visual
description. Google `gemini-nano-banana-2.1` generates a 1K, 4:3 image; the worker
uploads the bytes to Cloudinary using a signed server-side request. The ordinary
chat model can use this tool; it does not need to become an image model.

Set `GEMINI_API_KEY` and `CLOUDINARY_URL` in the worker environment or ignored
local `.env`. Both are GitHub repository secrets. Provisioning can supply them
through `runtime_secrets`, and `sync-llm-secret.py` can merge both into the worker
Secret when given them in its environment during an authorized release. The
Actions workflows still need to forward these two secrets through `ci.yml`'s
release call and `deploy.yml`'s declared secrets/deploy environment. The prepared
workflow patch is local because the publishing credential lacks GitHub's
`workflow` scope; repository secrets alone do not reach running containers.
Neither credential belongs in the API or frontend. This change does not deploy
or enable the release switch.

Apply migration `015_recipe_images.sql` before running the new API/worker. It adds
an optional message image and a generation ledger, retaining existing messages.
The normal runtime grant procedure covers the new table. Migration 014 is
reserved by the separate policy-settings PR and is not required for images.

`RECIPE_IMAGES_ENABLED=false` disables generation. Optional settings:
`RECIPE_IMAGE_MODEL` (default `gemini-nano-banana-2.1`),
`RECIPE_IMAGE_TIMEOUT_SECONDS` (45), and `RECIPE_IMAGE_HOURLY_LIMIT` (5 per buyer).
The assistant chooses useful recipe illustrations, especially on explicit image
requests; ordinary product/status questions stay in text. Only dish appearance
should be sent to Google, never personal details or entire conversations.

One generation attempt is allowed per persisted customer message. Its ledger is
created before calling Google, under the buyer's hourly limit. Concurrent calls,
successful retries and interrupted workers cannot generate another image for
that message. Ambiguous timeouts/crashes require a new message to request another
generation. There are no automatic paid retries.

Generated bytes are saved before upload. Retrying an interrupted turn can finish
hosting without another generation; the random public ID remains stable. Uploads
overwrite only that same generated image. Bytes are cleared after successful
upload. Pending bytes older than 24 hours are discarded on that buyer's next
image-tool request. A provider/hosting failure lets the assistant continue with
text. A completed text-only turn is not rerun by retrying the accepted HTTP request.

Only the hosted URL and dimensions are saved with the assistant message and
returned through the existing authenticated API/SSE. Refreshing chat shows the
same image. The frontend labels it **AI-generated illustration**, loads it without
a referrer, and preserves text if the image disappears. CSP permits Cloudinary's
delivery host. Cloudinary uses public, unguessable image URLs; do not generate
sensitive content. Temporary hackathon accounts/credits must be retained or
replaced before their expiry for images to remain available.

Illustrations are not source recipe photographs or proof of ingredients,
allergens, portion sizes, product availability or purchasing authority. No model,
embedding, guardrail or purchase policy is changed by this tool.

Provider contracts: [Google images](https://aistudio.google.com/docs/image-generation),
[Cloudinary signed upload](https://cloudinary.com/documentation/image_upload_api_reference#upload_method),
[signature calculation](https://cloudinary.com/documentation/authentication_signatures).
