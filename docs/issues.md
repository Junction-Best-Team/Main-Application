# Cross-track issues

Use this file for anything one track needs from another, including contract changes. Open the issue against the **provider** track. The provider either fixes it, or replies with a counter-proposal. Contracts are versioned; a change is announced here, never made silently. GitHub issues are fine too, but keep a one-line pointer here.

Entry format:

```
### I-<nnn>: <short title>
- Opened: YYYY-MM-DD by Track <n>   Against: Track <n>   Contract: C<n> (or none)   Status: open | answered | done | wontfix
- Need: <what is required, with an example request or response>
- Reply: <provider's answer, date>
```

Mark an issue `done` only once the consumer has checked it against the real provider (or its stub), and say what was run.
